3. FROZEN MODEL
============================================================

DO NOT MODIFY recovery_model.py.

Understand its equations exactly.

The energy is approximately:

    E(a) =
        0.5 * a^T R a
        - (eta / beta) * log(sum_i exp(beta * x_i^T a))

The gradient is:

    g(a) =
        R a
        - eta X^T softmax(beta X a)

The Hessian is:

    H(a) =
        R
        - eta * beta * X^T (diag(s) - s s^T) X

where:

    s = softmax(beta X a)

The precision-controlled dynamics are:

    update =
        - pi elementwise_multiply gradient
        + external_input

During the initial input window:

    external_input = corrupted_query

After T_in:

    external_input = 0

The Euler update is:

    a_next = a + dt * update

The model runs until T_max or convergence.

Final classification is based on cosine similarity between the final state and stored patterns.

CRITICAL CONCEPT:

Positive diagonal precision does not fundamentally change the stationary points of the underlying energy because the equilibrium condition is still approximately:

    gradient = 0

Precision primarily changes HOW THE TRAJECTORY GETS THERE.

Therefore this is fundamentally a:
    BASIN / TRAJECTORY / CONVERGENCE CONTROL
problem.

Do not approach it as merely "predict the hidden class."

6. EXACT SCORING
============================================================

There are 100 total points.

Recovery accuracy:
    70 points

Convergence balance:
    20 points

    10 points

Automated maximum is therefore 90.

------------------------------------------------------------
6A. RETRIEVAL ACCURACY
------------------------------------------------------------

For every seed:

    baseline_acc = accuracy with pi = 1

    agent_acc = accuracy using our precision controller

    delta = agent_acc - baseline_acc

The mean delta across seeds is used.

Full retrieval points occur at:

    mean delta >= +0.08

The retrieval score scales linearly between:

    delta = 0       -> 0 points
    delta = +0.08   -> 70 points

If any evaluated seed has:

    delta < 0

the retrieval score is halved.

Therefore CONSISTENCY IS EXTREMELY IMPORTANT.

A controller that produces +0.15 on one seed and -0.05 on another is dangerous.

A stable +0.04 across seeds can be more valuable than an unstable +0.10.

------------------------------------------------------------
6B. BALANCE / ANISOTROPY
------------------------------------------------------------

For selected stored patterns, the evaluator:

1. finds the true equilibrium under uniform precision
2. computes Hessian H at that equilibrium
3. probes our adapter with a lightly perturbed version of the pattern
4. gets our precision vector
5. computes:

    sqrt(pi) H sqrt(pi)

6. measures its eigenvalue spread.

Baseline:

    pi = 1

Reduction:

    baseline_spread / agent_spread

Full balance score occurs at:

    5x reduction

Scoring is logarithmic.

If mean reduction <= 1:

    zero balance points.

If ANY evaluated seed has reduction <= 1:

    balance score is halved.

Therefore we need balance improvement to be robust too.

============================================================
10. IMPORTANT OBSERVATION ABOUT THE CORRUPTION
============================================================

The corruption process is informative.

Masked dimensions become:

    approximately Gaussian noise around zero.

Observed dimensions retain signal from the source pattern plus noise.

Therefore |q_i| contains some information about whether a dimension survived corruption.

But:

    high |q_i|

does NOT automatically mean:

    high reliability.

A naturally large pattern coordinate may be highly ambiguous across stored patterns.

Likewise a small coordinate may still be highly discriminative.

Investigate reliability relative to X rather than using only |q|.

============================================================
11. USE THE STORED PATTERNS
============================================================

The stored patterns are available.

For each query, investigate:

    z_k = beta * X_k dot q

and:

    p_k = softmax(z)

Then investigate the posterior-like reconstruction:

    m = sum_k p_k X_k

This gives a query-conditioned estimate of what the model currently believes the pattern looks like.

Study:

    q_i
    m_i
    q_i - m_i
    q_i * m_i
    |q_i - m_i|
    |q_i|
    variance of X[:, i]
    agreement of candidate patterns at dimension i
    disagreement between top candidate patterns at dimension i

These quantities may provide better precision signals than raw query magnitude.

But be careful:

If the top candidate is wrong, blindly reconstructing from it can reinforce the wrong basin.

Investigate mixtures of competing candidates rather than only argmax.

============================================================
12. COMPETING-PATTERN ANALYSIS
============================================================

Because patterns are clustered, the difficult cases are likely to involve similar stored patterns.

For each query, investigate:

    top-1 candidate
    top-2 candidate
    top-k candidates

Then compare dimensions where candidates disagree.

For example:

    d_i = |X_top1[i] - X_top2[i]|

A dimension that strongly separates the leading candidates may be strategically important.

However, if q_i is corrupted on that dimension, aggressively trusting it could be harmful.

Therefore consider:

    candidate disagreement
    ×
    query reliability

rather than either independently.

Investigate whether precision should emphasize:

    reliable discriminative dimensions

while suppressing:

    corrupted ambiguous dimensions.

============================================================
13. R MATTERS
============================================================

R is not decorative.

The dynamics contain:

    R a

Therefore dimensions are coupled.

Study:

- diagonal R_ii

- local coupling
- graph/Laplacian structure
- correlations between R and X

============================================================
14. HESSIAN / PRECONDITIONING
============================================================

The Hessian is:

    H = R - eta*beta*X.T@(diag(s)-s s.T)@X

The balance metric explicitly evaluates:

    sqrt(pi) H sqrt(pi)

A natural starting point is diagonal equilibration/preconditioning.

For example:

    pi_i approximately proportional to 1 / H_ii

or related diagonal scaling.

But do not assume that simple inverse diagonal is optimal.

Investigate:

- 1 / H_ii
- 1 / sqrt(H_ii)
- Ruiz-style diagonal equilibration
- iterative diagonal scaling
- condition-number reduction
- eigenvalue spread reduction
- query-dependent H
- equilibrium H
- approximating equilibrium H from q
- blending curvature scaling with query reliability

Remember that pi is mean-normalized and clipped by the harness.

============================================================
15. RETRIEVAL AND BALANCE ARE DIFFERENT OBJECTIVES
============================================================

This is a major part of the problem.

A precision vector that improves Hessian conditioning may not improve retrieval.

A precision vector that improves retrieval may make anisotropy worse.

Do not blindly maximize one metric.

Think of:

    precision =
        retrieval component
        +
        geometry/balance component

with robust normalization.

Investigate mixtures such as:

    pi = reliability_component
         * curvature_component

or convex/log-space combinations.

But test them empirically.

============================================================
16. VERY IMPORTANT: PRECISION AFFECTS TRAJECTORY
============================================================

Because:

    a_next = a + dt*(-pi*g + q)

during the input period,

changing pi changes the relative speed at which different dimensions respond to:

- the external query
- the energy gradient
- coupling through R
- attractor forces

This means a good controller may intentionally:

- slow down unreliable dimensions
- accelerate trustworthy dimensions
- equalize effective convergence rates
- suppress dimensions whose gradient would pull the state toward a competing attractor
- emphasize dimensions that preserve the identity of the source pattern

Think of pi as a diagonal preconditioner for a nonlinear dynamical system.

20. POSSIBLE BALANCE OPTIMIZATION
============================================================

For balance, investigate diagonal preconditioning.

The evaluator's quantity is:

    S = sqrt(pi) H sqrt(pi)

and wants a small eigenvalue spread:

    lambda_max(S) / lambda_min(S)

A good diagonal scaling can approximately equalize curvature.

Investigate iterative scaling schemes.

For example, conceptually:

    pi = ones(N)

    repeatedly:
        S = sqrt(pi) H sqrt(pi)
        estimate per-dimension stiffness
        modify pi
        normalize mean(pi)=1

But make sure the final precision also remains useful for retrieval.

Do not sacrifice retrieval merely to get balance points.

A robust target may be:

    retrieval first
    then enough geometry correction to safely exceed 1x balance on every seed.
